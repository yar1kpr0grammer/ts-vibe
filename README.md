# ts-vibe

Интерактивный CLI для быстрого создания современных TypeScript-проектов под Node.js.

`ts-vibe` настраивает структуру проекта, TypeScript, npm-скрипты и выбранные инструменты разработки. Интерфейс построен на [`@clack/prompts`](https://github.com/bombshell-dev/clack) и следует привычному сценарию `create-vite`.

## Возможности

- готовая рекомендуемая конфигурация;
- ручной выбор инструментов;
- поддержка ESM и CommonJS;
- типы Node.js;
- алиас `@/*` для каталога `src`;
- современный ESLint Flat Config;
- тестирование через Vitest;
- Prettier;
- README для создаваемого проекта;
- инициализация Git и создание первого коммита;
- русский и английский интерфейс;
- создание без установки зависимостей через `--skip-install`;
- безопасная работа с непустыми директориями;
- транзакционная генерация и автоматический rollback при ошибке.

## Требования

- Node.js 20.12 или новее;
- npm;
- Git (опционально).

## Запуск

Без глобальной установки:

```bash
npx ts-vibe
```

Или установите CLI глобально:

```bash
npm install --global ts-vibe
ts-vibe
```

Чтобы создать файлы проекта без запуска `npm install`:

```bash
npx ts-vibe --skip-install
```

После генерации CLI покажет необходимые команды:

```bash
cd my-project
npm install # только при использовании --skip-install
npm start
```

## Процесс создания проекта

CLI последовательно предложит:

1. Ввести имя проекта. Используйте `.` для текущей директории.
2. Выбрать поведение, если целевая папка не пуста.
3. Выбрать рекомендуемый или ручной режим настройки.
4. В ручном режиме выбрать возможности и систему модулей.
5. Проверить итоговую конфигурацию.
6. Подтвердить создание проекта.

До финального подтверждения `ts-vibe` не изменяет файловую систему.

## Режимы настройки

### Recommended

Рекомендуемый вариант создаёт ESM-проект и включает:

- Git;
- `README.md`;
- типы Node.js;
- алиас `@/*` → `src/*`.

### Custom

Ручной режим позволяет выбрать:

| Возможность | Что добавляется |
| --- | --- |
| Git | `.gitignore`, `.gitattributes` и Git-инициализация |
| README.md | Документация создаваемого проекта |
| Node.js types | `@types/node` и типы Node.js в `tsconfig.json` |
| `@/` path alias | Алиас `@/*` → `src/*` |
| ESLint | ESLint Flat Config для TypeScript |
| Vitest | Vitest, пример теста и команды запуска |
| Prettier | Конфигурация и npm-скрипт форматирования |

Также можно выбрать `module` или `commonjs`. ESM-проекты используют `NodeNext`, поэтому проверка типов, компиляция и запуск через Node.js следуют одним правилам разрешения модулей.

## Предпросмотр конфигурации

Перед генерацией CLI показывает:

- имя и абсолютный путь проекта;
- режим работы с целевой директорией;
- систему модулей;
- выбранные возможности;
- необходимость установки зависимостей;
- поведение Git;
- список создаваемых файлов.

Это позволяет проверить настройки до любых изменений на диске.

## Генерируемый проект

Базовая структура:

```text
my-project/
├── src/
│   └── index.ts
├── package.json
└── tsconfig.json
```

В зависимости от выбранных возможностей также могут быть созданы:

```text
├── .gitattributes
├── .gitignore
├── .prettierignore
├── .prettierrc
├── eslint.config.mjs
├── src/index.test.ts
└── README.md
```

### npm-скрипты

Каждый проект получает базовые команды:

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Запустить проект через `tsx` в watch-режиме |
| `npm start` | Запустить `src/index.ts` один раз |
| `npm run check` | Проверить типы без создания JavaScript-файлов |
| `npm run build` | Скомпилировать TypeScript в `dist` |
| `npm run prod` | Запустить собранный `dist/index.js` |
| `npm run lint` | Проверить проект ESLint, если он выбран |
| `npm test` | Запустить Vitest в watch-режиме, если он выбран |
| `npm run test:run` | Выполнить тесты Vitest один раз |
| `npm run format` | Отформатировать проект, если выбран Prettier |

## ESLint

При выборе ESLint создаётся `eslint.config.mjs` на основе Flat Config и устанавливаются совместимые версии:

- `eslint`;
- `@eslint/js`;
- `typescript-eslint`;
- `eslint-config-prettier`;
- `globals`.

Игнорирование `dist` и `node_modules` настраивается непосредственно в Flat Config, поэтому отдельный `.eslintignore` не создаётся.

## Vitest

Vitest доступен в режиме `Custom` и не включается в рекомендуемый минимальный профиль. При выборе этой возможности создаётся `src/index.test.ts` с простым примером теста и добавляются команды:

```bash
npm test          # интерактивный watch-режим
npm run test:run # однократный запуск
```

Используется Vitest 4, совместимый с минимальной поддерживаемой версией Node.js 20.12.

## Безопасность генерации

Проект сначала полностью подготавливается во временной staging-директории внутри ожидаемой целевой папки. Поэтому во время установки рядом не появляется каталог с техническим именем `.ts-vibe-stage-*`:

1. Создаются файлы.
2. При необходимости устанавливаются зависимости.
3. Инициализируется новый Git-репозиторий.
4. Готовый проект публикуется в целевую директорию.

Если создание или установка нового проекта завершается ошибкой, созданная целевая папка удаляется целиком. Для существующего проекта временные файлы удаляются, а исходное содержимое восстанавливается.

После успешной подготовки файлы публикуются из внутреннего staging-каталога. При объединении с существующей папкой используется журнал изменений и backup для rollback.

### Работа с Git

- Для нового самостоятельного проекта создаётся репозиторий и первый коммит.
- Внутри существующего Git-репозитория `ts-vibe` не создаёт вложенный репозиторий.
- В существующем репозитории CLI не выполняет автоматические `git add` и `git commit`, чтобы не захватить пользовательские изменения.

## Язык интерфейса

Язык выбирается автоматически на основе системной локали:

- `ru` — русский;
- остальные или неизвестные локали — английский.

## Разработка

Клонируйте репозиторий и установите зависимости:

```bash
git clone https://github.com/yar1kpr0grammer/ts-vibe.git
cd ts-vibe
npm install
```

Запуск CLI из исходного кода:

```bash
npm start
```

Запуск автоматических тестов:

```bash
npm test
```

Тесты проверяют:

- декларативный план ESLint;
- транзакционное создание нового проекта;
- режимы очистки и объединения;
- сохранение `.git`;
- rollback при ошибке установки;
- безопасную передачу аргументов без shell.

## Архитектура

Ключевые модули:

| Файл | Ответственность |
| --- | --- |
| `src/project/setup.mjs` | Интерактивный сбор настроек и предпросмотр |
| `src/project/features.mjs` | Декларативное описание возможностей |
| `src/project/transaction.mjs` | Staging, публикация и rollback |
| `src/cmd.mjs` | Безопасный запуск дочерних процессов |
| `src/utils/cmd.mjs` | Компоненты терминального интерфейса |
| `languages/` | Русская и английская локализации |
